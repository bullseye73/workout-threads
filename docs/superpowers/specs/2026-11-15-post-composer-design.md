# 게시물 작성 흐름 · 종목별 목표 · 테마 설정 이동 — 설계

작성일: 2026-11-15 · 상태: 승인됨 (2026-11-15)

> **범위 메모 (2026-11-15):** 이번에는 7.4 목표와 7.5 테마만 구현한다. 게시물 작성 흐름(2절 1–5, 6절, 7.1–7.3)은 보류. PWA(모바일 업로드)는 검토 후 제외: 모바일에서 FIT 파일을 받아 올리기 어렵다.

## 1. 의도
- **게시물 작성:** 지금은 FIT와 사진을 먼저 정해진 폴더(예: `sns_create/20261025/`)에 날짜별로 모아 두고 "가져오기"를 해야 한다. 사용자는 이것이 불편하다. "게시물 작성" 화면에서 어디에 있는 파일이든 올리면, 앱이 한곳(앱 보관함)에 저장·관리하고 그 자료의 날짜로 게시물을 만들기를 원한다.
- **목표:** 월 목표가 라이딩·러닝 합계 하나라 러닝 거리는 목표에 거의 드러나지 않는다. 종목별 목표가 필요하다.
- **테마:** 상단 줄의 테마 버튼은 자주 쓰지 않는 설정이라 설정 창으로 옮긴다.

## 2. 목표
1. 상단 "가져오기"를 없애고 그 자리에 "게시물 작성"을 둔다.
2. 게시물 작성 창에 FIT·사진을 끌어다 놓거나 고르면, 저장 전에 무엇이 만들어질지 미리 보여 준다.
3. "게시물 만들기"를 누르면 파일을 앱 보관함으로 복사하고, **FIT마다 운동 하나와 게시물 하나**를 만든다. 원본 파일은 옮기거나 지우지 않는다.
4. 만든 게시물 목록을 보여 주고, 누르면 그 운동의 게시 준비 탭이 열린다.
5. 운동 상세에 "보관된 자료"(FIT, 원본 사진, 카드의 보관 위치)를 보여 주고 폴더를 열 수 있다.
6. 라이딩 목표와 러닝 목표를 따로 정하고 보여 준다.
7. 테마(시스템/밝게/어둡게)를 설정 창으로 옮긴다.

## 3. 비목표
- 게시는 여전히 사용자가 직접 한다(스레드 자동 게시 없음).
- 운동 없이 글만 쓰기, 한 운동에 글 여러 개.
- 원본 파일 정리·삭제, 보관함 파일 지우기.
- 걷기·하이킹 등 다른 종목의 목표.

## 4. 실패로 보는 것
- 미리보기와 실제로 만들어진 결과가 다르다(다른 사진이 붙거나 다른 날짜에 생김).
- 붙일 운동이 없는 사진이 보관함에 쌓인다.
- 이미 있는 운동을 다시 올렸을 때 운동·게시물이 중복으로 생긴다.

## 5. 방법 (검토한 것)
1. **미리보기 후 만들기 — 채택.** 파일을 놓으면 백엔드가 저장 없이 읽어(FIT 요약, 사진 촬영 시각·짝) 계획을 돌려주고, 확인 후 같은 규칙으로 저장한다. 잘못 고른 파일을 복사 전에 뺄 수 있어 "한곳 관리"에 맞다. 대가: 읽기 전용 미리보기 기능 하나가 더 필요(기존 짝 맞추기 코드 재사용).
2. 놓자마자 만들기 — 가장 단순하지만 잘못 넣은 파일도 보관함에 들어간다. 탈락.
3. 가져오기 이름만 바꾸기 — 폴더에 미리 모으는 불편이 남는다. 탈락.

## 6. 규칙
### 6.1 운동
- FIT 하나 = 운동 하나 = 게시물 하나(템플릿 글 자동 작성, 지금과 같음).
- 날짜는 FIT 시작 현지 시각의 날짜(자정을 넘긴 운동도 시작일).
- 이미 보관된 FIT(같은 운동 ID)는 새로 만들지 않고 "이미 있는 운동"으로 표시하며, 누르면 그 게시물을 연다.
- 읽을 수 없는 FIT는 "읽을 수 없는 파일"로 표시하고 만들지 않는다.

### 6.2 사진 (내 결정, 사용자가 수정 가능)
붙이는 순서:
1. 이번에 올린 운동 중 시간(운동 중 또는 ±10분, 기존 규칙)이 맞는 운동.
2. 보관함에 이미 있는 운동 중 시간이 맞는 운동(기존 `activities_near` 범위).
3. 촬영 날짜에 운동(이번 것 + 보관함)이 **하나뿐**이면 그 운동(km 지점 비움).
4. 어디에도 못 붙이면 **보관하지 않고** "붙일 운동이 없어 제외"로 표시. 촬영 날짜가 없는 사진도 제외("촬영 날짜가 없어요").
- 사진만 올려도 된다(이미 있는 운동에 사진 보태기).
- 이미 보관된 사진(같은 내용)은 다시 복사하지 않는다. 그 사진이 보관함에서 아직 안 붙은 상태라면 아래 "보관함의 안 붙은 사진"과 같은 규칙으로 붙을 수 있고, 이미 붙어 있으면 "이미 있음"으로 표시한다. *(내 결정)*
- **보관함의 안 붙은 사진:** 새 운동을 만들 때, 보관함에 남아 있던 안 붙은 사진에도 1~3번 규칙을 적용해 붙인다(지금의 다시 맞추기를 넓힌 것). 미리보기에 "보관함에 있던 사진 N장이 이 운동에 붙어요"로 보여 준다. 4번(제외)은 보관함 사진에는 적용하지 않는다(이미 보관된 것을 지우지 않음). *(내 결정)*
- **"그날 운동이 하나뿐" 판단:** 그 날짜의 모든 종목 운동을 센다. 보관함에 있는 운동(이번 "이미 있는 운동" 포함) + 이번에 새로 만들 운동. 사용자가 "빼기"로 뺀 FIT는 세지 않는다. *(내 결정)*
- **이미 고쳤거나 게시한 글:** 그런 운동에 사진이 붙으면 카드는 만들지만 글은 바꾸지 않는다(지금 규칙 유지). 미리보기에서 그 운동 옆에 "글은 이미 고쳤거나 게시해서 그대로 둬요"를 보여 준다. *(내 결정)*
- **폴더:** 폴더를 고르거나 놓으면 하위 폴더까지 찾는다(깊이 3단계까지, 숨김 폴더와 앱이 만든 `_card` 파일은 제외). 예전에 날짜 폴더로 모아 둔 자료를 상위 폴더째 올릴 수 있게. 파일 수가 많으면 미리보기 동안 "읽는 중… N개"를 보여 준다. *(내 결정)*
- 시간대: 사진 EXIF에 오프셋이 없으면, 짝이 된(또는 같은 날의) 운동의 오프셋, 없으면 이 PC 시간대. 미리보기와 저장이 같은 계산을 쓴다.

### 6.3 미리보기와 실제의 일치
- 미리보기는 저장하지 않고 6.1·6.2의 결과(운동 목록, 각 운동에 붙을 사진, 제외 목록과 사유)를 돌려준다.
- "게시물 만들기"는 미리보기에 남아 있는 파일만 같은 규칙으로 저장한다. 사용자가 미리보기에서 뺀 파일은 넣지 않는다.

## 7. 화면
### 7.1 게시물 작성 창 (Dialog)
```
┌ 새 게시물 ───────────────────────────────────┐
│ 여기에 FIT와 사진을 끌어다 놓거나 [파일 고르기] [폴더 고르기] │
│                                                │
│ 만들 게시물 2개                                    │
│  🚲 10월 25일 일요일 오후 라이딩 48.2km   사진 ▢▢   [빼기] │
│  🏃 10월 26일 월요일 이른아침 러닝 8.1km  사진 없음 [빼기] │
│ 이미 있는 운동 1개                                  │
│  🚲 10월 11일 일요일 오전 라이딩  [열기]              │
│ 기존 운동에 보탤 사진 1장   ▢ → 10월 11일 라이딩         │
│ 제외 2개                                          │
│  IMG_0412.jpeg  붙일 운동이 없어 제외                 │
│  screenshot.png 촬영 날짜가 없어요                    │
│                                                │
│ 올린 파일은 앱 보관함에 복사돼요. 원본은 그대로 둬요.        │
│                      [취소]  [게시물 2개 만들기]        │
└────────────────────────────────────────────────┘
```
- 창이 열려 있는 동안 앱 창에 끌어다 놓으면 이 창에 추가된다. 창이 닫혀 있을 때 끌어다 놓으면 이 창이 열리며 추가된다.
- 파일을 더 놓으면 목록이 다시 계산된다. "빼기"는 그 운동과 그 운동에만 붙을 사진을 뺀다. 개별 사진을 누르면 그 사진만 뺀다.
- 만들 게시물·보탤 사진이 하나도 없으면 만들기 버튼은 꺼진다.
- 결과 목록은 "만든 게시물"(새 운동)과 "사진을 보탠 운동"(기존 운동) 두 묶음이다. 사진만 올린 경우 "사진을 보탠 운동"만 나온다.
- 만들기가 끝나면 창 안에 "게시물 2개를 만들었어요" 목록을 보여 주고, 항목을 누르면 그 달로 이동해 그 운동의 게시 준비 탭을 연다. 하나만 만들었으면 바로 연다.
- 새 운동의 장소·날씨 채우기는 지금처럼 만든 뒤 하나씩 진행한다.

### 7.2 운동 상세의 "보관된 자료"
- 기록 탭 아래쪽에 접을 수 있는 칸: FIT 파일 이름, 사진 N장(원본), 카드 N장, 보관 폴더 경로와 "폴더 열기".

### 7.3 없어지는 것
- 상단 "가져오기" 메뉴(파일/폴더), 사진 띠 빈 칸의 "기록 추가", 상세 머리의 "이 날짜에 기록 추가", `DayImport` 패널, 날짜 지정 끌어다 놓기.
- 백엔드 `import_for_date`와 그 명령은 새 흐름이 대체하므로 지운다(테스트 포함). 기존 `import_paths`는 새 저장 단계의 기반으로 남기거나 정리한다(빌더 결정).
- "안 붙은 사진 N장" 버튼과 수동 붙이기는 **남긴다**: 예전에 들어와 붙지 않은 사진이 라이브러리에 있을 수 있다.

### 7.4 목표
- 목표 창: "라이딩 목표 (km)", "러닝 목표 (km)" 두 칸. 비우면 그 종목 목표 없음.
- 상단 줄: 정한 종목마다 작은 막대 하나(종목 색, 오늘 기준선, "하루 N km면 목표"는 막대마다). 둘 다 없으면 지금처럼 합계 거리와 "목표 정하기".
- 기존 합계 목표(`monthly_goal_km`) 값은 **라이딩 목표로 옮긴다**(지금까지 라이딩 목표처럼 쓰였으므로). *(내 결정)*

### 7.5 테마
- 상단 줄의 테마 버튼을 없애고, 설정 창 맨 위 "화면 테마"에 같은 세 가지 선택을 둔다.

## 8. 바뀌는 곳 (빌더가 정할 것)
- `workout-service`: 미리보기 `plan_upload(paths) -> UploadPlan`(저장 없음), 저장 `commit_upload(paths) -> UploadResult`, 사진 붙이기 규칙 6.2를 미리보기·저장이 함께 쓰는 한 함수로. 종목별 목표 설정 두 개와 `MonthView`의 목표 필드 변경, 기존 값 이전. 운동 상세에 보관 자료 정보(FIT 상대 경로, 사진·카드 경로, 폴더).
- `src-tauri`: 명령 추가·삭제.
- `ui`: `Composer` 창(새), TopBar 버튼 교체·테마 제거, `goalProgress`를 종목별로, Settings에 테마, 상세에 보관 자료 칸, 날짜 지정 관련 코드 삭제, App의 끌어다 놓기 연결.
- 테스트: 샘플(10/11, 10/25)과 합성 JPEG(`real_jpeg_with_local_time`)로 6.1·6.2 규칙, 미리보기 = 저장 결과, 중복, 제외; 화면 계산은 vitest.
