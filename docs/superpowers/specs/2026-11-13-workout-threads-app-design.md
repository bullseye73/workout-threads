# 운동 기록 → 스레드 게시 준비 앱 설계

작성일: 2026-11-13
상태: 승인 대기

## 1. 목적과 배경

지금은 날짜 폴더(예: `20261025/`)에 Garmin FIT 파일과 사진을 넣고,
`tools/fit_card.py` + `tools/card.swift`로 카드 이미지를 만든 뒤 Claude에게
"초안 A" 형식의 스레드 글을 받아 사용자가 직접 게시한다.

이 흐름을 **mac / Windows / Linux에서 도는 데스크톱 앱 하나**로 옮긴다.
앱은 운동 기록을 쌓아 월간 대시보드와 달력으로 보여 주고, 날짜별로
게시용 글·해시태그·카드 이미지를 준비해 준다. 게시는 사용자가 직접 한다.

성공 기준: FIT와 사진을 넣으면 한 화면에서 그날 기록 확인 → 글 복사 →
카드 저장까지 끝나고, 한 달 운동량을 Garmin Connect 화면처럼 한눈에 본다.
데이터는 구글 드라이브에 백업돼 다른 PC에서도 이어 쓸 수 있다.

## 2. 목표 / 비목표 / 실패 조건

**목표**
1. FIT 파일(러닝·라이딩)과 여러 장의 사진(EXIF 메타데이터 포함)을 입력한다.
2. 메인 화면: 해당 월의 운동량 대시보드 (첨부된 Garmin Connect 화면의 카드 배치 참고).
3. Rust로 개발, mac / Windows / Linux 지원.
4. 날마다 러닝·라이딩 기록을 달력에 표시한다.
5. 운동 상세: 2D 지도에 경로와 시작·종료 지점 핀, 상세 지표 그래프.
6. 구글 OAuth 로그인, 구글 드라이브에 데이터를 매일 저장(백업).
7. 날짜별 게시 준비물: 초안 A 형식 글 + 해시태그 + 카드 이미지.

**비목표 (이번 범위 아님)**
- 스레드 자동 게시 (단, 나중에 붙일 수 있게 구조는 열어 둔다 — §6.6).
- Garmin 일상 데이터(바디 배터리, 스트레스, 수면, 일일 걸음 수, 혈압).
  활동 FIT에 없고 공식 API도 개인에게 열려 있지 않다.
- 3D 지도 애니메이션 / 릴스용 영상 생성 (map-route 스킬 결과물 같은 것).
- 모바일 앱, 여러 사용자 계정.

**실패 조건 (동작해도 실패로 보는 것)**
- 특정 OS에서만 되는 기능이 생기는 것 (지금 카드가 macOS Swift 전용인 문제의 반복).
- 집 근처일 수 있는 출발·도착 좌표나 정확한 위치가 글에 그대로 노출되는 것.
- 드라이브 동기화 때문에 로컬 데이터가 망가지거나 사라지는 것.

## 3. 제약

- 언어: Rust (사용자 지정). 화면은 Tauri의 웹 화면(TypeScript) 허용 — 사용자가 Tauri를 선택.
- 지도 타일: OpenStreetMap 기본 타일 서버, 개인 사용량 수준. 타일 공급자는 설정으로 바꿀 수 있게 한다.
- 구글 OAuth: 사용자가 자신의 Google Cloud 프로젝트에서 "데스크톱 앱" OAuth 클라이언트를
  만들어 클라이언트 ID를 앱 설정에 넣는다. 권한은 `drive.file`만 쓴다.
- 기존 규칙 유지: 글은 반말체, 출발·도착 좌표/장소는 글에 쓰지 않는다,
  장소명이 좌표로 추정한 것이면 추정임을 표시한다.

## 4. 접근 방식 (검토한 것)

| 방식 | 내용 | 장점 | 단점 |
|---|---|---|---|
| **1. Tauri 2 (선택)** | Rust 코어 + 웹 화면 | 지도(Leaflet)·차트·대시보드 모양을 내기 쉬움, 3 OS 설치 파일, OAuth 흐름 성숙 | 화면은 TypeScript |
| 2. egui | 순수 Rust | 실행 파일 하나, 한 언어 | 대시보드 꾸미기 어려움, 지도 품질 낮음 |
| 3. Slint / iced | 순수 Rust | — | 지도 지원이 약해 거의 처음부터 만들어야 함 |

사용자가 1번을 골랐다. 이유: 앱의 중심이 대시보드·달력·지도 같은 보는 화면이고,
Rust 코어를 분리하면 "Rust로 개발" 목적도 지킨다.

대시보드 데이터 범위도 검토했다: (A) 운동 기록만, (B) Garmin 일상 데이터 포함,
(C) A로 시작 후 B. 사용자가 **A**를 골랐다 (Garmin 데이터를 바로 가져올 수 없음).

지도는 (a) 2D 지도만, (b) 2D + 영상 내보내기 중 **2D 지도만**으로 정했다.

## 5. 전체 구조

코드 재사용을 위해 기능은 UI와 분리된 Rust 라이브러리에 둔다.

```
workout-app/                     (Cargo workspace)
├─ crates/
│  ├─ core/        도메인 모델, FIT 해석, 사진 EXIF, 통계, 사진↔기록 매칭
│  ├─ card/        카드 이미지 렌더링 (순수 Rust, 폰트 내장)
│  ├─ post/        초안 A 글 + 해시태그 생성, Publisher 트레이트
│  ├─ store/       로컬 저장소 (SQLite + 파일)
│  └─ gdrive/      구글 OAuth + 드라이브 동기화
├─ src-tauri/      Tauri 앱: 위 crate들을 묶어 명령(command)으로 노출
└─ ui/             웹 화면 (TypeScript): 대시보드, 달력, 상세, 게시 준비
```

`core`·`card`·`post`는 UI·네트워크 의존이 없어 CLI나 다른 화면에서도 그대로 쓸 수 있다.
CLI(`workout-cli <폴더>`)를 하나 두어 기존 `fit_card.py` 사용 방식도 대체한다 (빌더 판단 가능).

## 6. 기능 설계

### 6.1 입력 (FIT + 사진)
- 입력 방법: 앱 창에 파일/폴더를 끌어다 놓기, 또는 "가져오기" 버튼.
  기존 날짜 폴더(`20261011/`, `20261025/`)를 통째로 가져오는 것도 지원한다.
- FIT: `fitparser` crate 사용. session(18)·record(20)·lap 메시지에서
  종목, 시작 시각, 거리, 이동 시간, 경과 시간, 평균/최대 심박, 평균 속도·페이스,
  고도 상승, 케이던스(있으면), 경로 좌표, 시간별 심박·속도·고도를 꺼낸다.
- 지원 종목: 러닝(1), 라이딩(2). 걷기·하이킹은 저장은 하되 대시보드 집계에서는 "기타"로 둔다.
- 하루에 여러 운동 가능 (오전 러닝 + 오후 라이딩).
- 사진: JPEG / PNG. EXIF의 촬영 시각·GPS·방향(회전)을 읽는다 (`kamadak-exif`).
  HEIC는 크로스 플랫폼 디코딩 부담이 커서 1차 범위에서 제외 (빌더 판단: 추후 libheif).
- 사진↔운동 매칭: 촬영 시각이 운동 시작~종료(±10분) 안이면 그 운동에 붙이고,
  FIT 기록 시각과 맞춰 "몇 km 지점"을 계산한다. EXIF 시각이 없으면 사용자가 운동을 고른다.
- 같은 FIT를 다시 넣으면 중복으로 막는다 (FIT 파일의 시작 시각+기기 시리얼 기준).
- 시간대: FIT `activity.local_timestamp`가 있으면 그것으로, 없으면 시스템 시간대.

### 6.2 메인 화면: 월간 대시보드
첨부 Garmin Connect 화면의 카드 배치를 따른다. 데이터는 모두 FIT 운동 기록에서 계산.

```
┌ 2026년 11월 ◀ ▶ ─────────────────────────────────┐
│ [총 거리]   [총 시간]   [러닝 n회]   [라이딩 n회] │  ← 원형 게이지 카드
├──────────────────────┬───────────────────────────┤
│ 러닝 • 주별 막대     │ 라이딩 • 주별 막대         │  ← "포커스" 카드
│ 거리 / 평균 페이스   │ 거리 / 평균 속도           │
├──────────────────────┴───────────────────────────┤
│ 달력 (6.3)                                         │
├──────────────────────────────────────────────────┤
│ 이번 달 요약 목록: 러닝 n회 · 라이딩 n회 · 평균 심박 │
└──────────────────────────────────────────────────┘
```
- 월 목표 거리 게이지: 제안 사항. 설정에서 목표를 넣으면 "목표 대비" 원형 게이지로,
  없으면 단순 합계로 표시.
- 월 이동(◀ ▶)으로 지난달 기록도 본다.

### 6.3 달력
- 날짜 칸마다 그날 운동을 아이콘 + 거리로 표시 (🏃 5.2km / 🚲 48km). 여러 개면 모두.
- 게시 상태 표시: 준비 안 됨 / 준비됨 / 게시함(사용자가 체크).
- 날짜를 누르면 그날 상세(6.4)와 게시 준비(6.5)로 이동.

### 6.4 운동 상세
- 2D 지도 (Leaflet): 경로 선, 시작 핀(녹색)·종료 핀(빨간색), 사진 촬영 지점 마커.
- 지표 요약: 거리, 이동 시간, 평균 페이스(러닝)/평균 속도(라이딩), 평균·최대 심박, 고도 상승, 케이던스.
- 그래프 (거리 축): 심박, 페이스/속도, 고도. 그래프 위 지점에 마우스를 올리면 지도에 위치 표시.
- 랩/km 구간표 (러닝은 1km 스플릿).

### 6.5 게시 준비 (글 + 해시태그 + 카드)
- **카드 이미지**: 기존 `card.swift`와 같은 디자인을 순수 Rust로 다시 구현한다
  (`tiny-skia` 그리기 + `ab_glyph`/`cosmic-text` 글자, 한글 폰트는 앱에 내장 — 예: Pretendard, OFL).
  - 위: 날짜, "요일 시간대 종목" 제목 / 아래: 큰 거리 숫자 + km, 보조 기록(시간 · 페이스나 속도 · 심박),
    거리 위에 흰 경로 선. 위·아래 그라데이션 음영. 긴 변 최소 2160px, JPEG 품질 92.
  - EXIF 회전 반영. 사진마다 카드 1장.
- **글 (초안 A 형식)**:
  1. 첫 줄: 요일·시간대 + 장소 + 거리 + 이모지 (예: "일요일 오후 한강 48km 🚲")
  2. 경로 한 줄 (A → B → C 찍고 복귀)
  3. 기록 한 줄: 평속(러닝은 페이스) / 이동 시간 / 평균 심박
  4. 사진 촬영 지점 이야기 한두 줄 ("몇 km 지점")
  5. 날씨·기온 한 줄
  6. 답글 유도 질문
  7. 해시태그 (종목, 장소, 코스 키워드)
  - 말투: 반말체 ("~했음", "~더라"). 출발·도착 지점 이름은 쓰지 않는다.
  - **글을 무엇으로 생성할지는 미정 — §8 참고.**
- 화면: 글 편집 상자(직접 고칠 수 있음) + "복사" 버튼, 카드 미리보기 + "저장 폴더 열기",
  "게시 완료" 체크.

### 6.6 게시 구조 (나중의 자동 게시 대비)
```rust
trait Publisher {
    fn publish(&self, post: &PostDraft) -> Result<PublishReceipt>;
}
// 지금: ManualExport (클립보드 복사 + 카드 파일 저장)
// 나중: ThreadsApi (Meta Threads Graph API)
```
- `PostDraft` = 글, 해시태그 목록, 카드 이미지 경로들, 연결된 운동 ID.
- `PublishRecord` = 게시 방식, 게시 시각, 외부 게시물 ID(나중), 상태. 지금부터 저장한다.
- Threads API는 공개 이미지 URL이 필요하다. 이미지를 어디에 올릴지는 자동 게시를 붙일 때 정한다.

### 6.7 저장소
- 로컬: OS별 앱 데이터 폴더 (`directories` crate).
  - `library.db` (SQLite, `rusqlite`): 운동, 요약 지표, 사진, 게시 초안, 게시 기록, 동기화 상태.
  - `files/YYYYMMDD/`: 원본 FIT, 원본 사진, 생성된 카드. 기존 날짜 폴더 구조와 같게 둔다.
- 경로 좌표·시계열 데이터는 원본 FIT에서 다시 계산할 수 있으므로 DB에는 요약과
  화면용으로 줄인 좌표(최대 1,500점)만 저장한다.

### 6.8 구글 로그인 + 드라이브 백업
- OAuth 2.0 설치형 앱 흐름: 시스템 브라우저로 로그인 → `127.0.0.1` 임시 포트로 돌아옴, PKCE 사용.
- 토큰(refresh token)은 OS 키체인에 저장 (`keyring` crate).
- 권한: `drive.file` (앱이 만든 파일만 접근).
- 드라이브 구조: `내 드라이브/WorkoutApp/` 아래 `files/YYYYMMDD/` 같은 구조 + `library.db` 스냅샷.
- 동기화 시점: (1) 새 운동/사진/카드가 생길 때, (2) 앱 시작 시, (3) 앱이 켜져 있으면 하루 한 번.
  앱이 꺼져 있으면 다음 실행 때 밀린 것을 올린다 ("매일 저장"의 실제 의미).
- 방향: 기본은 로컬 → 드라이브 단방향 백업. 새 PC에서는 "드라이브에서 복원"으로 내려받는다.
  두 PC에서 동시에 쓰는 양방향 동기화는 1차 범위 밖 (빌더 판단).
- 실패 시 재시도 대기열에 두고 화면에 마지막 백업 시각/실패 표시. 로컬 데이터는 절대 지우지 않는다.

## 7. 사용자가 정한 것 (요약)
- 게시는 직접, 앱은 글·카드 준비까지. 단 자동 게시를 나중에 붙일 수 있게 설계.
- 대시보드는 FIT 운동 기록만 사용 (방식 A).
- 지도는 2D만, 영상 없음.
- Tauri 2 (Rust 코어 + 웹 화면).

## 8. 글 생성과 장소·날씨 (사용자 결정)

### 8.1 글 생성: 템플릿 기본 + Claude로 다듬기 (사용자 선택 "다")
- **기본(오프라인)**: `post` crate의 템플릿이 초안 A 7줄을 채운다.
  자동으로 채우는 것: 첫 줄(요일·시간대·장소·거리·이모지), 경로 줄, 기록 줄,
  사진 지점 줄("N km 지점에서 찍은 사진" 수준의 뼈대), 날씨 줄, 해시태그.
  답글 유도 질문은 종목별 기본 문장 몇 개 중 하나. 사용자는 편집 상자에서 고친다.
- **Claude로 다듬기(선택)**: 버튼을 누를 때만 Claude API를 호출해 템플릿 초안을
  초안 A 규칙(반말체, 출발·도착 지점 이름 금지, 추정 장소 표시)에 맞춰 다시 쓴다.
  - API 키는 설정에서 입력, OS 키체인에 저장. 키가 없거나 실패하면 버튼만 비활성/오류 표시, 템플릿 글은 그대로.
  - 모델: 최신 Claude 모델을 설정값으로 둔다(기본은 빌더가 claude-api 레퍼런스로 확인).
  - 보내는 데이터: 템플릿 초안, 요약 수치, 장소·날씨 텍스트, 사진 촬영 지점 km.
    **좌표는 보내지 않는다.** 사진 이미지는 사용자가 "사진도 보내기"를 켰을 때만,
    GPS를 지운 축소본으로 보낸다(사진 이야기 줄을 자동으로 쓰기 위함).
  - 결과는 편집 상자에 덮어쓰기 전에 미리보기로 보여 주고, 적용/취소를 고른다.
- `post` crate 안에서 `DraftWriter` 트레이트로 분리: `TemplateWriter`, `ClaudeWriter`.

### 8.2 장소·날씨: 자동 입력 + 수정 가능 (사용자 결정)
- 장소명: Nominatim 역지오코딩. 날씨: Open-Meteo 과거 날씨(운동 시작 시각, 시간 단위 기온·날씨 코드).
- **위치 보호**: 경로 시작·끝 각 500m 안쪽 좌표는 보내지 않는다. 경로를 거리 기준으로
  나눈 중간 지점(최대 5개)만 보내 장소명과 "A → B → C" 경로 줄을 만든다.
  날씨는 경로 중간 지점 1개의 좌표를 소수 2자리(약 1km)로 반올림해 보낸다.
- Nominatim 정책 준수: 초당 1건 이하, 앱 이름이 담긴 User-Agent(개인 정보 미포함), 결과는 DB에 캐시.
- 자동으로 가져온 장소명은 "추정"으로 표시. 장소·경로·날씨 칸은 게시 준비 화면에서
  각각 수정할 수 있고, 수정값이 자동값보다 우선하며 다시 가져와도 덮어쓰지 않는다.
- 인터넷이 안 되면 빈 칸으로 두고 직접 입력.

## 8-1. 검토 후 정한 것 (설계자 판단)
- **배포**: 개인 사용 전제. GitHub Actions 등으로 3 OS 각각 빌드(서명 안 함:
  mac `.dmg`, Windows `.msi`, Linux AppImage). 코드 서명·공증·자동 업데이트는 범위 밖.
  각 OS에서 가져오기 → 대시보드 → 카드 생성 → 드라이브 백업을 한 번씩 수동 확인.
- **드라이브 복원**: 로컬 라이브러리가 비어 있을 때만 허용. 데이터가 있으면 복원 버튼을 막고
  안내만 한다 (병합은 범위 밖). 로컬 데이터가 사라질 일을 원천 차단.
- **OAuth**: 구글 데스크톱 클라이언트는 client secret도 필요하므로 ID와 함께 설정에 넣는다
  (데스크톱 앱 특성상 비밀로 취급되지 않음, 보호는 PKCE로).
- **대시보드 총 거리**: 러닝+라이딩 합계, 종목별 거리는 포커스 카드에서 따로.
- **위치 보호**: 생성된 카드 JPEG와 드라이브에 올리는 사진 사본에는 EXIF GPS를 지운다
  (원본 사진은 로컬에 그대로). 카드는 게시용이므로 위치가 새지 않게.
- **기존 데이터**: 날짜 폴더 가져오기 때 `_card.jpg`는 원본 사진으로 취급하지 않고 건너뛴다
  (카드는 앱이 다시 만든다).
